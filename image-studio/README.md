# Holzwerkskunst Bildstudio

A static browser application for turning reference photos into product images.
It runs without a Node.js backend and sends requests directly to OpenAI.

## Hosting and local preview

The GitHub Pages workflow runs `npm run build:image` after generating the catalog.
This bundles the official [OpenAI JavaScript SDK](https://github.com/openai/openai-node)
with esbuild and writes a self-contained browser module plus the public assets
and SDK license to `dist/bootstrap/image/`. No CDN or runtime package imports are needed.
After deployment the studio is available at **https://holzwerkskunst.de/image/**.
No server process, environment variables, or shared API key are needed on the host.
The built contents of `dist/bootstrap/image/` can be served by any static HTTP(S) host.
Use HTTP(S), rather than opening HTML with a `file://` URL, for JavaScript modules.

For an optional local preview, use Node.js 22 or newer, install dependencies with
`npm ci`, then run `npm run start:image`. Its `prestart:image` hook builds the studio,
and the static server opens
**http://127.0.0.1:4201/** using the existing static `http-server` package.
Stop it with Ctrl+C. Node.js is needed only for these development commands,
the catalog build, and tests; visitors need only a modern browser and internet access.

## API key

Open **API-Schlüssel** at the bottom of the page, enter your own OpenAI API key,
and choose **Im Browser speichern**. The header button jumps to these settings.
Without a key, image uploads, cropping, and manual prompt preparation still work.
Saving checks formatting only and makes no paid request. Use **Browser-Schlüssel
löschen** to remove it, or save a replacement. The masked field stays empty after saving.

The key is stored under `holzwerkskunst.image-studio.api-key` in browser Local
Storage. Storage is specific to the browser profile and origin; localhost,
127.0.0.1, different ports, and the public domain each have separate storage.
Other tabs on the same origin receive changes through storage events. Storage
failures are reported without claiming a key was saved or deleted.

Local Storage is unencrypted and accessible to scripts on the same origin.
[OpenAI recommends keeping keys secret on a server](https://developers.openai.com/api/reference/overview#authentication).
This deliberately browser-only tool uses each visitor's own key; do not publish
a shared key in public files. It is sent only as an Authorization header to
`https://api.openai.com`, never to the static host or exchange-rate service.
Running requests retain the key they started with. No credentials go in URLs,
responses, or logs. Old `.env.image` files are ignored and are no longer read;
there is no server-key fallback. This uses API project billing and permissions,
independently of a ChatGPT subscription.

## Workflow

Each image has one horizontal row with three columns:

1. **Originalbild:** upload or drag in a JPG, PNG, or WebP image.
2. **Produktbild-Prompt:** click **Bild analysieren** to create a German product
   photography prompt from the uploaded reference. Or type your own prompt directly.
   **Prompt verbessern** rewrites the current text into a clearer German prompt,
   preserving its creative intent and constraints. It sends only the text and
   selected format; no image is transmitted or generated by this action. Both
   buttons replace the field only after success, so failures and cancellation
   preserve your work. Review/edit the text, choose an output format, and click
   **Bild generieren** explicitly to start generation. Analysis is optional when
   entering a prompt manually. Text improvement is available even before uploading.
3. **Ergebnis:** inspect the generated image and download it as JPG.

Click or tap a result image to open a full-window view. The image fits the screen
without cropping. Close with × or Escape; keyboard focus returns to the preview.
The same JPG download is available in this view. Opening it makes no API request.

JPG downloads are encoded locally at 95% quality with the image's full pixel
dimensions. Transparent areas are flattened onto white. The unmodified PNG
response remains the preview and reference for follow-up edits, avoiding repeated
JPEG compression. JPG conversion makes no extra API request.

Below each result, enter a follow-up prompt in **Was möchtest du am Ergebnis ändern?**
and click **Bild anpassen**. This sends the currently displayed generated image
and the exact entered prompt to the image editing endpoint, without another
analysis. Each successful adjustment becomes the reference for the next one,
retaining that result's output size even if the original row's format changes.
The original upload and reviewed generation prompt stay available separately.
The field clears on success; on failure or cancellation it and the previous image
remain available for retrying or downloading. Each click is a new paid generation,
listed as **Anpassung** in the per-request, row, and session costs. Download any
version you want to keep before replacing it with another successful generation.

Draft prompts are always written in German, including for instructions entered in
another language. Names and visible product inscriptions retain their original
spelling and language. Generation uses the reviewed German prompt verbatim.

You can select multiple files immediately; each gets its own row and independent
draft, status, and result. The three-column layout stays horizontal
on narrow screens and can be scrolled sideways. Up to 20 images can be loaded in
one browser session, with at most three API requests in progress at once.

Uploads are limited to 10 MB and 40 megapixels per image. Output defaults to
**1024 × 768 (4:3)** to match the catalog's image requirements. Square and portrait
formats are also available. After changing the image or output format, check and
edit the prompt, improve it, or analyze again before generating. Manually editing
the text marks it as reviewed for the current reference and format.

Neither uploads nor results are automatically saved to the repository or browser
storage. Download results before reloading or closing the page. Generated images
are not automatically added to `products/`. Check lettering and product details
before using a generated image. Cancelling aborts the browser request; an
already accepted OpenAI request may still incur API usage.

### Rotate and crop a reference

Choose **Drehen & zuschneiden** below an uploaded image. Rotate left or right in
90° steps, drag a crop rectangle, move it, or resize its corners. Choose a free
crop or 4:3, 1:1, or 3:4. Pixel fields provide a keyboard alternative to dragging.
The crop ratio is independent of the generated image's output format.

**Änderungen übernehmen** applies the preview to that row's reference. **Abbrechen**
or Escape discards pending edits. **Original wiederherstellen** previews the
initial upload again; apply to restore it. Reopening an editor retains the current
crop and rotation and always renders from the initial upload, avoiding cumulative
quality loss. These edits are local and make no API requests or charges.

After applying a change, check/edit the prompt or analyze again before generating.
Existing drafts, results, and cost history are retained; older results are labelled. Both
the next analysis and generation receive the edited reference. JPEG references
remain JPEG; other formats export as PNG to preserve transparency. The same 10 MB
limit applies to the edited image. Source files on disk are never modified.

## Configuration

Public model names, supported sizes, and input limits are in
`public/config.mjs`. Never put credentials there. The default analysis model is
`gpt-5.6-terra`; image generation uses `gpt-image-2.5-sunburst`.
Model access depends on the visitor's API project.

Analysis uses the [Responses API](https://developers.openai.com/api/docs/guides/images-vision)
with the reference image. Prompt improvement uses the same API with text only.
Generation and follow-up changes use the [image edits endpoint](https://developers.openai.com/api/reference/resources/images/methods/edit)
with one reference and the reviewed prompt, requesting one medium-quality PNG.
The official `openai` SDK handles these calls through `client.responses.create`
and `client.images.edit`. References are uploaded as browser `File` objects using
multipart requests. `dangerouslyAllowBrowser: true` explicitly enables the chosen
personal browser-key workflow. The client snapshots the key for each request,
omits cookies and referrers, rejects redirects, and disables SDK logging.
Automatic retries are disabled (`maxRetries: 0`) so each action makes one attempt;
retries remain explicit user actions in the cost history. Cancellation signals,
timeouts, German error messages, and reported usage on failures are preserved.

## Request costs

After every analysis, prompt improvement, or generation, the UI shows an **estimated euro cost** based
on the API response's token usage. The row total includes retries. Expand
**API-Kosten dieser Sitzung** to see every attempt, its model, input/output tokens,
price date, and conversion rate. Removing a row or replacing its image does not
remove past requests from the session total. This history is kept only in browser
memory and resets on reload; it cannot recover earlier requests or charges.

Standard USD token prices are centralized in `public/costs.mjs`, checked on 2026-10-30
against official OpenAI documentation:

| Model                                                                                                    | Input per 1M tokens    | Output per 1M tokens |
| -------------------------------------------------------------------------------------------------------- | ---------------------- | -------------------- |
| [gpt-5.6-terra](https://developers.openai.com/api/docs/models/gpt-5.6-terra)                             | $2; cached reads $0.20 | $12                  |
| [gpt-image-2.5-sunburst](https://developers.openai.com/api/docs/models/gpt-image-2.5-sunburst) and Flare | Text $5; image $8      | Image $30            |

Analysis accounts for reported cache reads/writes and the documented long-context
surcharge. Reasoning tokens are already included in output usage. Direct image
edits do not receive cached-input discounts. Unknown models, unsupported service
tiers, or incomplete usage display **Kosten unbekannt**. Failures retain any usage
the API reports. Cancelled or disconnected requests may still be billed even when
their usage cannot be received; these are never treated as free. Requests rejected
locally before contacting OpenAI are explicitly marked as not sent.

The browser fetches the latest daily ECB USD-to-EUR reference rate through the
public, CORS-enabled [Frankfurter API](https://frankfurter.dev/), explicitly selecting
the ECB provider, and caches it in memory for six hours. Only a public currency
query goes there; no images, prompts, or credentials are sent. A failed refresh
uses the last available rate, labelled in the history. If no rate is available,
the USD estimate remains visible and the euro total marks that request as unknown.
Totals retain precision before display rounding to four decimals.

These are reference-price estimates, not invoice amounts. Taxes, payment fees,
negotiated discounts, other applications' usage, and account billing adjustments
are excluded. Check the OpenAI dashboard for actual billing.

## Development and checks

`npm run test:image` runs protocol, credential, cancellation, pricing, exchange-rate,
and static-build checks with mocked API responses. It makes no paid OpenAI calls.
For visible changes also inspect the app in a browser, including at a nested
`/image/` path and on a narrow screen.

- `build.mjs`: bundles the SDK with esbuild, verifies no external imports remain,
  and copies an explicit allowlist of public assets and the SDK license into the catalog output.
- `public/index.html`, `studio.css`, `studio.js`: browser interface and row state.
- `public/config.mjs`: public model settings and limits.
- `public/openai.mjs`: validation and direct OpenAI calls using the official SDK.
- `public/costs.mjs`: versioned USD prices and cached EUR conversion.
- `public/image-editor.js`: local rotation/cropping dialog and canvas export.

There are no `/api/` routes, backend modules, or environment-file configuration.
The public HTML restricts scripts to its own origin and connections to its own
origin, OpenAI, and the public currency feed through a Content Security Policy.
